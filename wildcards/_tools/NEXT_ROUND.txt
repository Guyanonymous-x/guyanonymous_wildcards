APPROACH (to confirm with user): do not hand-write thousands of builders. 
 1. Script classifies each head noun into an object class (furniture seat/table/storage, fixture, appliance, container, paper/printed, tool, textile, sign, plant, vehicle part, etc.).
 2. One component template per class (type/form, material, finish, colour, period, wear, size, detail), filled from shared pools already in the library (materials, colours, finishes) plus class-specific pools researched where thin (research rule).
 3. Generator writes per-object files: <obj>_type, _material, _finish, _colour, _style, _era, _condition, _short, _full, _random, _phrase, same naming as existing families, no colons in descriptions, names+descriptions and description-only forms.
 4. Location records then reference these builders, so a location pool entry like "lockers" expands to a randomly built locker.
 5. Manual hand-written pools for the top few hundred by frequency; template output for the long tail.
 6. Re-runnable per batch as the dataset grows; check_build.py verifies references.
PLACEMENT: starts with the v75 pilot (objects needed by the first 325 records), then each release adds the objects for newly finished location batches. Items overlap with 70 (books/periodicals), 71 (signage), 73 (vehicle interiors), 63 (architecture); build those first so they are not duplicated.

Many specific details in the Location Inventory (for example "sticky floor", worn carpet, flickering tube light, peeling paint, smell of fryer oil) fit far more environments than the one record they were written for. At import, do not bind details only to their source location. Split each record's details into generic detail pools by type (surface, wear, smell, sound, light behaviour, clutter, trace, stain, fixture) with compatibility tags (enclosure, function, condition, climate, era, materials), so a detail can be drawn into any location whose tags fit. Source-location pools stay for faithful scenes; the shared pools drive cross-use. Converter should dedupe near-identical details and record which locations each came from, as the fit list.

ITEM 82 DECISION (added 2026-11-03 19:08) Two-tier details, kept in both places. Every detail stays in its own location's pool (representative of that scene) AND is compiled into shared "anywhere" pools built automatically from all locations, the same way objects are pooled. Per location: loc_<slug> (clean scene, no extras), loc_<slug>_details (that location's own subset, wildcard-referable), plus shared loc_any_<type> pools (surface, wear, smell, sound, light, clutter, trace, stain, fixture), with tag-filtered variants (loc_any_<type>_<tag>) so only fitting details come through. Entry points compose in layers: the clean scene, then optional N from the location's own details, then optional M from anywhere pools filtered to the location's tags. Variants per location: _clean, _own, _mixed, _anywhere. The converter builds the shared pools by pooling and deduping, so adding a location batch refreshes them with no hand work.
