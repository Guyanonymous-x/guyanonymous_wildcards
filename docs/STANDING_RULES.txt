# Guyanonymous' Wildcards - STANDING RULES (check before writing ANY prompt, wildcard, showcase or release)

## 0. TEXT RULES (highest priority, set by the user 2026-11-04, repeated many times - never skip)
Source: MOSS_IMAGE_NOTES (our tests + OpenMOSS technical report). The model (text encoder Qwen3.5-9B) draws any word it is shown.
1. If text SHOULD appear on a sign, label, tag, packaging, badge, cap, t-shirt, card, book cover, poster, screen: write it verbatim in quotes, one line per text, say where it is ("on the first line", "on the second line"). Use the fake name system (name_* files) so the text is invented, not a real brand.
2. If text should NOT appear: do NOT mention it at all. Never write "no other words", "no readable text", "no lettering", "nothing else", "unlettered". Negations did not help in tests and the words invite lettering. Describe the surface positively: plain, unmarked, blank, decorated with shapes and patterns only.
3. Never mention label, tag, badge, sign, banner, wordmark, logo, slogan, caption, packaging text unless the text on it is defined in quotes.
4. Before every release, scan new/changed lines for undefined text mentions and for text negations. Report what was checked.
5. Brand styles are objects STYLED like a brand, never branded products: the file name carries the brand (maker_bs_heinz); the prompt text never names the brand, never says "in the style of <Brand>", and puts no logo/wordmark on every object. Style = colour, shape, material, pattern. A logo may appear small on packaging, labels or signs only. The object is already bought; it is not selling itself.
6. Fake names only: websites end in .example, phones use 555, no real brands/people outside maker_ files.

## 1. Content rules
- Natural-language prompts for txt2img (Moss Image). Everything fully described, never relying on a name or jargon alone; jargon described visually.
- All content from the wildcard system plus only joining words.
- Adult content: adults only, consensual; no minors or youth-coded wording (no school/student), no animals, diapers, real hate insignia, non-consent, NO urine/feces; knives/needles as objects only, never in use. Levels L1-L6 (L1-L5 four adults or fewer; L6 ejaculate/squirting/groups of five+); no crowds/audiences in L1-L5. Leave the six "...50..." prompt files as is.

- Promo text includes the GitHub reference line (https://github.com/Guyanonymous-x/guyanonymous_wildcards).
- Git: cloud clone, push main directly, release/vNN branches, never force-push/reset main. Commit trailers: Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com> and Claude-Session line.
- Zips over 30 MB go via SendUserFile only; small files also to the user's !Releases\vNN folder.
- VERSION FOLDER CONTENTS (user 2026-11-05): every !Releases\vNN folder holds exactly these ten files and nothing else: Guyanonymous_Wildcards_vNN_FLAT.zip, _FOLDERS.zip, _NOTPROPORTIONAL_FLAT.zip, _NOTPROPORTIONAL_FOLDER.zip, _promo.md, _sample_prompts.txt, _sample_prompts_labelled.tsv, _showcase_1024.txt, _showcase_1408.txt, _showcase_key.tsv. Check the folder against this list after every release.
- Short answers, start work in the first reply, tell the user what was checked.

- Test prompts for the user are always given in the showcase line format: --prompt "..." --steps 50 --cfg_scale 3.75 --seed N --width W --height H (in the reply and in the file).

- Text on products is fine and wanted: define it in quotes, one line each with position, using the random name system (name_brand, name_type_<group>, name_variant_<group>, name_weight_<group>); do not use the "plain and unmarked" sentence when text is meant to appear.

- Brand styles are about design mentality and styling trends, never about one object type: no shoe, bag, car etc. words in a style unless the brand is only ever that object; describe linework, curves, proportions, materials and palette that can apply to any object.

- FEATURE-GRID SHOWCASE (user 2026-11-04, a SEPARATE showcase set, not part of the normal 40-prompt release showcase): 2 to 3 prompts for EACH distinct body feature of men and women (including hair), each prompt a grid of 4 to 9 cells showing the variability the wildcard system gives that feature, with nothing else changing between cells and the feature dominating the frame (for example nose: 2-3 grid prompts of various noses). Covers every distinct body part, including clinical three-quarter views of genitals, breasts, buttocks and anuses, and expressions (a range of expressions, including those from the adult components of the system). Not every variant needs showing, only 4 to 9 per prompt. Adults only, all existing adult rules apply. Describe the grid physically (rows and columns, each cell a separate view on a plain background, evenly spaced). Pull cell content from the feature wildcards, not hand-written.
- BRAND-STYLE PROMPT STRUCTURE (user 2026-11-04, supported by the technical report: training captions run subject, then environment, then style): put the object first and tie the style to it ("A wallet done in a design language of ..."), keep the style clause short, repeat the object once at the end; no "The subject is X" tail. Brand marks are an optional add-on (__bs_mark__) built from random shape, material, outline, size, place plus a fake logo and name from the name system.

- The body-feature grid showcase files, their generator scripts and any other test or private prompt files are NEVER committed or pushed to GitHub and NEVER put in a version folder (user 2026-11-05): deliver them in chat only. Keep them out of the repo, release branches, the library zips and !Releases.

- SAMPLE vs SHOWCASE FILES (user 2026-11-04): in every version zip/release, the sample prompt files must be samples of EVERYTHING the package can do (spread across all prompt families and entry points, not just this version's additions). The showcase files focus on version-specific additions and improvements. Build samples from all entry points, weighted so every major family appears.

DOCUMENT WORDING (each version): accompanying documents (README, index, promo, release notes) say that SHOWCASE files highlight the features that are new or changed in that version, while SAMPLE files are representative of everything the model can do.
- SEMEN VOLUME (user 2026-11-05): keep semen amounts small and realistic (about a teaspoon, rarely a tablespoon); describe small streaks and beads, never pools, drenching or heavy loads.
- BODY-FEATURE SHOWCASE RULES (user 2026-11-05, replace the older feature-grid wording above where they differ): (1) grids are 2x2 or 2x3 at most (the generator uses 2x3) (3x3 and 1x6 drop or duplicate panels); (2) all grids for one body part or feature show the SAME person, with the same clothing, light and background, so only the feature changes; different features may use different people; (3) the frame is a close-up of just that part (a chin, one hand, one foot), turned about thirty degrees toward the left of the frame so the front and a little of the side show, never a whole head or arm; (4) every image carries ONE title in its bottom left corner (once per image, not per panel), quoted: "[Feature] Variations" in the singular (Eye Variations, Pose Variations), with "Guyanonymous' Wildcards" in smaller text beneath it; (5) each panel is a bracketed self-contained photograph so nothing leaks between panels; (6) cells are spread across the real options (size, shape, grooming) and the rest of the visible body (waist, hips, thighs, torso) is written to match each shape, never the skin colour; (7) poses go last: solo, two-person and three-person grids with the same people in the same outfits in every panel, outfits chosen to suit the pose (leotard for yoga, sportswear for action, formal wear for ballroom); (8) tool: _tools/V106_showcase_generator.py (274 grids, all 2x3). Files are named Guyanonymous_Wildcards_vNN_bodyfeature_showcase_* so the release copy step never picks them up; they stay out of git.
- Every version still needs the normal 40-prompt version showcase (v106: _tools/v106_showcase.py), which IS committed under docs/showcase.
- CHIN (user 2026-11-05): never write a deep cleft; a cleft chin is a small shallow dimple low on the chin tip with the outline unbroken.

Body-feature showcase clothing (v107): every body-part and feature grid (features, age, skin marks, tattoos, makeup) shows the person completely nude, stated in every panel. Only pose grids (solo, two-person, three-person, and the yoga, dance and martial-arts activity grids) have clothing, the same outfit in every panel, chosen to suit the activity.


Body-feature showcase size and layout (v107, user rule): ONE grid per body part per gender, and one per pose type. Keep the whole set near the original ~100 prompts; never multiply grids per feature. Output as separate files for women, men and group poses, with each feature's grid kept together. Every panel in a grid must be a clearly different type (one panel per class, plain exaggerated wording such as "deeply hooded eyes, a heavy fold of skin hanging over the upper lids so that no lid shows at all"), never subtle wording variants. The part that changes leads each panel; "same person, nude, same background" is said once in the grid header. Anything that is not the feature (eye colour, lashes, makeup on an eye grid; skin colour elsewhere) is fixed in the header.

- CHECK THE ORIGIN BEFORE CALLING ANYTHING WRONG (user 2026-11-05): before proposing to change existing library lines, find why they were written that way (docs/BRIEF_*, ADULT_QUESTIONS_*, INDEX_vNN, _tools/VNNN_CHANGES.md, git log for the file) and state that reason to the user next to any proposal. Most of the library was written by Claude in earlier sessions to rules the user set; judge lines by the brief they were written to, not by newer rules for other files. Example: adult_l6_location crowd lines are one 10-35 word sentence with five or more adults by design (BRIEF_v85_adult, v85 answers, v87 crowds removed from L1-L5 only).
- SEEDS (user 2026-11-06): give every prompt its own widely varied random seed (6 to 10 digits, kept below 2147483647), never sequential runs such as 10901, 10902. Use the same seed only when a test needs it (for example comparing wording with everything else fixed). The expansion seed that picks wildcard lines is separate from the image seed.
- IMAGES FROM THE USER (user 2026-11-06): every image the user sends may carry its prompt and settings in the PNG metadata (the 'parameters' text: prompt, negative prompt, LoRAs, seed, variation seed, model). Read the metadata first, with PIL Image.open(path).info, and use it when judging or fixing a prompt.
- BRAND NAMES IN SOURCE MATERIAL (user 2026-11-06): when a real brand or organisation name has to be removed (text rule 6), replace it with a description that keeps the look of that brand (colour, shape, material, pattern), and add brands with a strong visual identity to the brand-style data (v83_bs_*.py rows) so the styling is available everywhere.
- CHILD-RELATED PLACES (user 2026-11-06): no prompt that involves a child-related location (schools, nurseries, playgrounds, children's wards and similar) is sexual in any way. People in those places are adults aged 25 and over in modest workwear; no phrase puts a child in a scene; no adult_ file references any loc_ file; the v109_loc child_safe_check must pass on every build.
- NEVER DELETE LIBRARY FILES FROM BUILD OUTPUT (2026-11-06): a vNN build only returns the files its own chain makes, not the whole library, so a file missing from build() is not evidence that it is stale. Retire files only from an explicit list of names the converter used to make and no longer makes (for example old loc_ pilot pools), check that list against the git clone, and run expand.py --check afterwards. (544 ob_ files were deleted by this mistake on 2026-11-06 and restored from the git clone.)
- Sample and test prompt files (including the medical scene samples) are private: never put them in release zips, version folders or git.
- SPECIALIST TERMS (user 2026-11-06): in every specialised area (card collecting and grading, medicine, sport, crafts, trades...), a term that is commonly understood with one clear meaning can stay; any term that is specialist, ambiguous or in doubt is described in plain visual words instead of relying on the text encoder to know it.
- WORDS ON CLOTHING (user 2026-11-06): jerseys and any sportswear or uniform with words, numbers, names or patches always quote the text, from the name system (name_team, name_jersey_number, name_first, name_surname).
- EVERY TEXT AREA DEFINED (user 2026-11-06): on cards, boxes, leaflets, boards and anything else with more than one place for words, every area that carries text gets its own quoted text with its position (title, corner numbers, rules line at the bottom, labels); a text area left undescribed fills with gibberish. Other cards in a scene lie face down showing a patterned back.

How to use it is kept in the project doc claude/LAYOUT_JSON_NOTES.md for future work. Never put layout JSON in wildcard files (braces are read as choice blocks).
