MOSS-Image notes (Guyanonymous' Wildcards project)
Sources: user handover; github.com/OpenMOSS/MOSS-Image README and USERGUIDE.md; comfyui-wiki.com/en/models/moss-image; arXiv 2610.23374 abstract page (full PDF could not be fetched, rate limited).

MODEL
- MOSS-Image, MOSI.AI / OpenMOSS. Technical report arXiv 2610.23374, submitted 16 Oct 2026, 35 pages, CC BY 4.0.
- 5B single-stream diffusion transformer pretrained from scratch; FLUX.2 latent space (flux2-vae); text encoder Qwen3.5-9B (a full LLM).
- Prompts up to about 4,000 tokens. Natural language, booru-style tags, or layout JSON (bounding boxes with per-box captions and a text field); natural language can be combined with structure.
- Variants Base (fine-tuning/LoRA) and SFT (generation). Runs in ComfyUI 0.42.0+.
- Report also describes an agentic prompt-enhancement module that expands user requests into detailed content and layout specs.
- Strengths claimed: bilingual (English/Chinese) long-form text rendering, layout control. LongLongTextBench 96.3% average text coverage (best open-weight). RealLayoutArena 2nd end-to-end.

GUIDANCE FROM USERGUIDE / README
- Guidance scale 3.0 is generally sufficient for long prompts; raise for short prompts. Example uses 50 steps, guidance 3.0.
- English recommended (most training data); other languages supported.
- Text to render: examples put the text in quotation marks, but no rule requires quotes. Use \n or real line breaks to control line breaks. Layout JSON uses a text field.
- Recommended negative tags: nsfw, worst quality, bad anatomy, watermark, jpeg artifact. Negative prompt empty by default in the Python API.
- Tag order if using tags: Quality, Score, Meta, Year, Character, Series, Artist, General.
- Layout JSON (experimental): summary {meta, canvas, caption} plus items [{label, caption, text, bbox}]; bbox_format yxyx; abs_centralized coordinates relative to canvas centre.
- No documented guidance on avoiding unwanted text.

OBSERVATIONS FROM OUR OWN TESTS (single seeds, not conclusive)
- Words like banner and birthday near decorations or cakes make the model draw lettering, including garbled text; negations such as no readable lettering did not help. Use positive wording (blank plain flags) and avoid the trigger words.
- Outfit and action bind to the right person well with ordinal and position anchors. Identity details (gender, age, skin tone) drift more, especially when the outfit carries gender cues. Neutral outfits plus an identity tag in the outfit sentence appeared to help.
- Exact people count held at 8 in most runs after adding an explicit count line; one SFT run at CFG 4 gave 9.
- CFG 3.25 to 4 changes only small details; CFG 4 introduced an attribute bleed once.
- Variation seed strength 0.55 with a random variation seed makes runs non-comparable.
- 1536x1536 took about 4 min 20 s per 50-step image; 1024x1024 about 1 min 35 s to 1 min 50 s on an RTX 5060 Ti 16GB.

USERGUIDE.md DIGEST (MOSS-Image-Base user guide, read 2026-11-03)
- Formats: natural language, tag sequences, JSON layouts, mixable. English recommended. No stated length limit; no guidance on multi-person prompts, counting, attribute binding or quoting rules.
- Inference settings: resolution 1M, 1.5M or 2M total pixels (extrapolates from 0.25M to 4M); arbitrary aspect ratio in multiples of 16; steps >= 50; CFG default 3.0 with range 3.0 to 6.0 (3.0 enough for long prompts, raise for short ones); shift 5.0; Euler recommended.
- Skip Layer Guidance: standard SLG scale 3, range 0.01 to 1.0; two-pass SLG uses uncond skip with layer 22 (0-indexed); layers 22, 24, 26 can all help. Turning SLG off gives very realistic output but some details may collapse.
- Negative prompt: nsfw, worst quality, bad anatomy, watermark, jpeg artifact (examples use shorter sets or none).
- Text rendering: examples quote the text; use \n or real line breaks to control line breaks; results may not match exactly.
- Base model has no post-training or CFG distillation; keep the text encoder frozen when training LoRAs.
- Layout JSON is experimental: summary {meta, canvas, caption}, items {label, caption, text, bbox}; bbox_format yxyx; abs_centralized pixel coordinates with the canvas centre as origin.
- Practical: 1024x1024 is 1.05M pixels; 1408x1408 is 1.98M (inside the recommended 2M); 1536x1536 is 2.36M (slightly beyond).

TECHNICAL REPORT DIGEST (arXiv 2610.23374v1, PDF read 2026-11-03)
- Data: about 3.2B images kept of 5.5B (dedup and AI-image removal only, no quality filtering). "Annotate rather than filter": watermarks, blur, compression artefacts are described in the captions instead of removing images (examples: "with a watermark at the bottom left", "The image quality is blurry and pixelated").
- Captions generated with gemma4 at three granularities: short (mean 21 tokens), medium (mean 77), long (mean 235, P90 293, longest sampled 3,126). Long = detailed account of composition, subjects, actions, environment, style, visible text. Sampling 20% original / 80% recaptions, short/medium/long 1:1:1. Predominantly English captions. Visible text transcribed verbatim with line breaks, quoted in captions.
- Structured layout JSON annotations on a high-quality subset; field dropout during training. Text-token cap 4096 in stages 3 and 4 (this budget includes layout JSON). Stage 3 area <= 1024^2, stage 4 up to about 2x1024^2; sizes multiples of 16.
- Conditions are concatenated and passed through the Qwen chat template, Qwen3.5-9B encoder.
- CFG sweep for FD metrics: best at CFG 3 for both runs.
- Evaluation: prompt strategies (design requests): short request 1082 Elo, natural 1506, detailed 1509, direct expansion 1541, JSON layout 1623 (best). Explicit content and layout instructions beat short prompts. Prompt enhancer is an external LLM agent (GPT-6 planner).
- Line breaks inside text help rendering; zero-centred absolute bbox coordinates generalise better across resolutions.
- Limitations stated: no reference-image conditioning or editing; prompt enhancer depends on external LLMs. Nothing said about multi-person scenes, counting or attribute binding.
- Implications for our prompts: (1) natural-language prompts of 2,700 to 3,500 tokens are far longer than the captions the model mostly saw (long captions about 150 to 300 tokens); the 4096 cap exists mainly for layout JSON. (2) Our opener names blur, haze, noise and compression artefacts, which are exactly the things the training captions annotate, so naming them (even negated) may invite them; prefer positive wording. (3) Layout JSON with one box and caption per person matches the training format and scored best in the paper's prompt-strategy test.

--- 2026-11-03 prompting guidance supplied by the user (source: a chat answer, NOT from the model card or paper; treat as working advice until tested) ---
1. No weights. Do not scale a tag with numbers or brackets ((happy:1.3)). Scale the vocabulary instead: standard = "a woman smiling pleasantly at the camera"; strong = "a bright, cheerful grin, laughing"; extreme = "an ecstatic woman, eyes closed in pure joy, cheering excitedly". Intensity is carried by the physical description (mouth, eyes, posture, action), not by a number.
2. Emphasis through detail. To make an object or trait dominant, describe its appearance, placement and lighting in more detail ("a highly prominent, bright red leather collar with a small gold bell") instead of repeating it or bracketing it.
3. Tag prompts (stylised or anime only): sequential commas, quality first then subject then details, no parentheses. UNVERIFIED: the "official tag sequence" and tags like score_9 look like a Pony-style convention; our model notes say only that natural language, booru tags or layout JSON are all accepted. Not used by this library.
Fit with our own findings: (a) our images already show the point, since physical descriptions were followed (scowling with arms folded, brow furrowed and jaw set; open-mouthed grin with glassy half-closed eyes) while bare names failed (soul patch, balbo beard, clean-shaven); (b) emphasis through detail is the same rule as our describe-the-object rule and is the fix path for facial hair and skin tone (items 52 and 53); (c) the library already has no weight syntax (0 files) and no LoRA tags.

--- 2026-11-03 user observation: framing statements are weak on every model ---
User reports that SD, SDXL, FLUX, Krea2 and Moss all cut people off and ignore statements such as "all in frame", "full body", "head to toe". Our own 12 images agree: "every person shown fully from head to toe" was in every prompt and feet were hidden or cropped in most images, and edge cropping at far left or far right happened in 3 of 12. Conclusion: do not rely on a framing instruction, build framing into the scene itself. Ideas to test (all keep the square 1:1 frame): (1) geometry in the scene, not a command ("a wide band of empty carpet in front of everyone's feet", "empty wall and ceiling above every head", "a clear gap of floor between the group and each side wall"); (2) place people so nobody overlaps legs, seat people on the floor or sofa, and keep standing people at the back with open floor in front of them; (3) fewer people per image (check the peoplecount results for where cropping starts); (4) a longer camera distance stated as distance ("taken from about five metres away") instead of lens words; (5) a first sentence about the empty space, since early words weigh more; (6) a taller subject count rule: at most two standing people.
User also reports percentage placement phrases ("feet in the bottom 15 percent of the image") help only sometimes. Include as one variant in the framing test next to the boilerplate, the geometry wording and the distance wording. Other routes outside wildcard text: render taller or wider and crop to square afterwards, outpaint, or a pose or layout control; layout JSON boxes were ignored for whole-body groups in our v6 test.
Idea (user, 2026-11-03, not yet tested): edge cropping may depend on how the model handles frame ratios. All tests so far are square 1:1. Test at about 1 megapixel with only the ratio changed: 1024x1024, 1184x896 (4:3), 1248x832 (3:2), 1360x768 (16:9); 8-person and 4-person short prompts, two seeds (16 lines). Square 1:1 stays the standing rule, so this would be a deliberate exception; if wide frames help, render wide and crop to square.

--- 2026-11-03 rules from the owner and from building the showcase file ---
TEXT IN IMAGES (owner): any text that should appear in a Moss image must be inside quotation marks in the prompt (for example the words "THIS WAY"). Text outside quotation marks is read as description. The library sign files already use quotation marks. In a batch-flags file the inner quotes are written \" so the line still parses.
BATCH-FLAGS FORMAT: one line per image, --prompt "TEXT" --steps 50 --cfg_scale X --seed N --width W --height H. Checked with shlex that all lines split into the prompt plus four settings. Files made earlier today without --prompt (the 16-person market file) were corrected.
SIZES at about 2 megapixels, multiples of 16: 1:1 1408x1408, 4:3 1632x1216, 3:2 1728x1152, 16:9 1856x1056, 2:1 1984x992, 5:4 1568x1264 and the portrait versions. Moss takes arbitrary ratios in multiples of 16 from 1 to 2 megapixels.

SHOWCASE GRIDS (user note 2026-11-03): when generating showcase prompts, a grid of up to 3x3 (nine small views or variants in one image) is acceptable for some objects (for example accessories, shoes, hats, tools, food). Use it where showing the variety of an object matters more than one big picture; describe the grid physically (three rows of three, each cell a separate item on a plain background, evenly spaced) and keep text-in-quotes for any labels.
